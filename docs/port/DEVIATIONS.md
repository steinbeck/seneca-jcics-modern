# Deviations of the port from the 2001 program

This document lists every place where the port behaves differently from the legacy code
(`legacy/original/src` + `legacy/dist-2001/seneca-client.jar`), with the reason, the `LegacyCompat`
mode it applies to, and the golden records it affects. Policy: docs/port/design.md section 1; switch
points: design.md section 5.

Columns: **Mode** = `STRICT` / `DEFAULT` / `both`. **Golden** = golden records whose values the
deviation changes (in the stated mode), or "none". **Status** = `planned` (designed, not implemented),
`implemented`, or `verified` (golden or oracle tests pass), with the owning work package.

Rules for implementers: add an entry before (or with) the code that deviates; never change a
STRICT outcome without an entry here; DEFAULT entries must state why runs in which legacy does not
fail are unaffected.

These changes have no observable effect on runs, except DV-61 (status text). For a spectrum with a second `<spectruminfo>` block, the reader follows the legacy loop exactly (it reads only the first block), so that behaviour is not a deviation.

## GUI (application)

Section 12 of docs/port/gui-design.md lists the deviations of the Swing application from the 2001 client
(DV-70 onwards: New Dataset, close-with-save as SML, current dataset, menus, look and feel, preferences,
run-slot labels, and others). None of them changes a score, a search, or a golden record.

## Kept on purpose (not deviations; listed so nobody "fixes" them)

D1 (Hybridization/HeteroBonds `init()` wipes the configuration), D2 (SymmetryJudge max = Σ k!/2),
D3/Q3 (FeatureJudge max 0), D4/Q5 (2D "satisfied" counts every rule), D12/D16 (assigner defects and
accumulation), Q4 (HeteroBondsJudge field hiding), kT = -0.0 regime, Morgan heuristic duplicate test,
HOSECodeJudge indexing `carbonShifts` by atom index, FeatureJudge calling the ring finder twice,
`Math.exp`/`Math.log` (not `StrictMath`), and `Double.toString` in descriptions. All of these determine
scores or the search, and the port reproduces them in both modes.

## The port's golden recorder (`seneca record`) compared with the harness

`cli.Main record` is not legacy behaviour; its differences from the harness are listed here for
whoever compares recordings. It produces the layout of `legacy/harness/run.sh` in one JVM with
parallel threads (the port has no static state; the harness needed one JVM per job). The records are byte-identical (`compare.sh`; `scripts/compare-golden.sh` checks
the exceptions below in one command with exit code 0), with these exceptions:
`runs/timing.jsonl` (wall times; `wallCapSeconds` is 0: the port has no wall-clock cap),
`PROVENANCE.json` (hashes of the legacy inputs; not produced), `MANIFEST.jsonl` (only with
`--manifest legacy/harness/summarize.py`), and `crash.at` inside the crash records (DV-30). The recorder
compresses trajectories with the system `gzip -n -9` (identical container) or, without it, with the JDK
(compare.sh: "gzip container differs, content identical"). The trajectory probe of the harness was a
pseudo-judge and added one `"\n"` to every `ScoreSummary.description` of a traced run (not recorded); the
port observes through `StepObserver` and changes nothing.
